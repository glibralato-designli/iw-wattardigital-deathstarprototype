# Death Star — prototype

A proof-of-concept redesign of the Stewart Group's prospecting portal (Wattar Digital × Designli), direction **5b · Navy shell**. Plain HTML, CSS and vanilla JavaScript; no installation or build.

## Open it
Live: https://glibralato-designli.github.io/iw-wattardigital-deathstarprototype/ (GitHub Pages from `main`; the product starts at `prototype.html`). Every push to `main` republishes it.

Locally:
```sh
python3 tools/preview.py
```
Open http://localhost:4173. The preview server disables caching and reloads on changes. Use `--port 4174` for another port. Every product page also works on its own (for example `pages/home.html`). Moving between screens never reloads the page: links are real links, but the runtime swaps the screen in place like an app, and back and forward work. Open a link in a new tab to load it on its own.

- `index.html`: the hub. Responsive web is active; the mobile card stays greyed out.
- `prototype.html`: the player. Its hamburger menu holds Light/Dark, the screen and state list, and Restart.
- `screens.html`: the canvas, every screen and declared state at 1440, 1024 and 390 (desktop, tablet and phone layouts).
- `system.html`: foundations, the 13 core families, and the Death Star product patterns.
- `pages/`: 13 product screens.

## The demo
Start on Home. The core loop: **Home → Call Daniel Marchetti → Why this? → Call → End call → No answer → Save outcome → Next owner.** Logged calls, notes, flags, to-dos, events and conversations persist in this browser; **Reset prototype data** (account menu, bottom left) or `?reset=1` restores the seed. Light and Dark are in the same account menu.

Keyboard: ⌘K search (⇧↵ opens the preview), ⌘J Brain, `[` sidebar, Esc closes.

Useful presets (URL parameters, also listed as states in the player): `home.html?layout=classic`, `?lead=upnext`, `?nav=rail`, `?brain=closed`; `attack-plan.html?called=all`, `?day=-1`, `?range=week`; `contact.html?id=marchetti&why=open`, `&call=live`, `&call=outcome`; `contacts.html?data=loading`, `?data=error`, `?peek=marchetti`, `?palette=search&pq=ludlow`; `brain.html?ask=list`; `calendar.html?dialog=new&clash=1`. `?calls=3` shortens Call next; `brain.html?think=3000` slows Brain.

## Files
```
DESIGN.md → css/tokens.css → css/base, layout, components → css/product.css → pages/
js/product-data.js (fixtures) → js/product.js (store, shell, Brain, ⌘K, peek, UI helpers) → js/screens/*.js
```
- `PRODUCT.md`: product context, flows, naming, open questions. `DESIGN.md`: the design system and its rules (source of truth for tokens).
- `config/project.js`: screens, flows, states and waivers for the player, canvas and portal export.
- `.claude/handoff/`: the Claude Design handoff this was built from (reference only).
- `tools/`: zero-dependency checks, token and icon sync, and the Design Portal export. `design/` is generated by the export; never edit it.

## Change it
- Tokens: edit the block in DESIGN.md, then `python3 tools/sync_tokens.py`.
- Icons: add Phosphor symbols to `assets/phosphor/icons.svg`, then `python3 tools/sync_icons.py`.
- New screen: add `pages/<id>.html` (copy an existing page; keep the hidden route list), a `js/screens/<id>.js` module that calls `DS.define()`, and a manifest entry in `config/project.js`.

## Validation
```sh
python3 tools/check.py
```
Checks token sync, light/dark contrast pairs (including the navy shell), typography tokens, icon sync, local links, IDs, labels and CSS variables.

## Version control and the portal
This folder has no git. To add version control: `git init`, then connect a **new** repository (never the template's). `/discovery-design-export` uploads the prototype to the Designli Design Portal and brings client feedback back.
